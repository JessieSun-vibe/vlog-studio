# 踩过的坑（第一支：海岛酒店 room tour vlog）

- **画幅**：用户拍横屏，参考视频是竖屏，被擅自改成 9:16，结果要么上下大留白、要么裁掉画面。用户：「要按我拍摄的角度来」。默认跟拍摄方向，改画幅先问。
- **不编造**：口播稿 / 字幕只写用户说过的信息。加了语气或判断的句子标出来让用户确认。用户实际录的口播和稿子不一样时，以录音为准（如「有点吵」实际是「晚上有海浪声」）。
- **口播稿别平淡**：开头一句结论当钩子，中间反问（「猜猜多少钱？」）和转折，结尾总结 + 推荐。
- **现场原声最有活人感**：一定要转写原视频的声音。「Happy Honeymoon!」「好喜欢这个床」「人家在用眼睛看呢」比口播更好，和口播重复的句子换成原声。
- **重复被识别器合并**：说了「床上摆着毛巾…床上摆着毛巾天鹅」，转写只出现一次，但某个字的时长被拉到 1–2 秒。看能量图找到停顿，切掉完整的第一遍。只切半句会留下「摆上摆着」。
- **句尾重叠**：每句口播各加 0.06/0.12s 余量 → 上一句尾字出现在下一句开头。相邻片段必须共用一个切点（`shared_cuts`）。
- **说错的词**（Fried 说成 Fair）：删整句，用字幕「然后炒面（Fried Noodles）的话」补正确信息。
- **识别错字**：巴厘岛→巴黎岛、海景→还景、藤编灯→藤边灯、潮→超、果昔→果西、4万印尼盾→4万亿一顿。字幕要逐句人工改。
- **复查转写也会「多一句」**：在安静段重复输出上一句。先看能量图再下结论。
- **画面对不上**：同一段素材的后半段可能拍到衣柜、空墙、模糊转场。每个镜头的起止都要对照缩略图挑，渲染后再出成片总表复查。素材不够长用慢镜头，不定格，不在相邻镜头重复用同一段。
- **网速**：第一次装 mlx-whisper 要下 torch 等几百 MB。118KB/s 时卡了 25 分钟，换网络后（680KB/s）几分钟就好。先 `curl -w "%{speed_download}"` 测速。
- **GitHub 大仓库**：`claude plugin marketplace add` 会超时，改用 `git clone --depth 1` 到本地再从本地添加。
- **看参考视频（小红书）**：agent-reach 只能拿到文字。用 Chrome 打开笔记，在页面里用 canvas 把 video 逐帧画成总表再截图。长视频每次只 seek 10 帧，避免超时。听不到声音，别声称知道配乐节奏。
- **贴图授权**：Noto 动态表情 CC BY 4.0，发布时附署名。素材库里标「not_yet_user_approved」的贴图要让用户看过再算确认。
- **ffmpeg 没有 drawtext**：所有文字用 PIL 画成 PNG 再 overlay。webm 贴图要 `-c:v libvpx` 解码才有透明。
- **变速**：用户确认过 1.2 倍。用 atempo 保持音调，SRT 同步缩放；加速后检查每秒超过 7 个字、停留短于 0.8s 的字幕。
- **版本**：每次输出 v1、v2…，不覆盖旧版本，告诉用户改了什么。

# 第二支：婚礼邀请（对镜自拍口播）
- **信息卡第一次放在画面中下方，压住了男生的脸**。挪到左边空的灌木处才对。放任何东西前先看人脸在哪。
- 派对礼花贴图贴着女生脸颊，也要挪开。webm 贴图播完就消失，放在角落也不怕抢戏。
- 戴墨镜、帽子也能认出人脸（YuNet），100% 帧都认到。某一帧少认到一张脸时按左右位置匹配，不会认错人。
- 同一句字幕跨两段，SRT 以前会拆成两条、加速检查还误报「读不完」，已改为自动合并。
- 用户会移动文件夹（素材和素材库都挪过）。路径找不到先搜、再问，不要假设。
